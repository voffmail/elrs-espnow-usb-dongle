# ELRS Backpack Telemetry: WiFi vs ESP-NOW — выбор под задачу

Практическая раскладка: когда для телеметрии с ELRS-бэкпака достаточно WiFi, а когда лучше купить и прошить USB-донгл на ESP32-C3.
Без экспериментов: выводы основаны на коде Backpack/ExpressLRS, физике диапазонов и известных ограничениях.

## Коротко

- **ELRS 900 МГц + дальние полёты:** WiFi-бэкпак подходит. Бэкпак работает на 2.4 ГГц, линк — на 900 МГц; общего диапазона нет, поэтому WiFi-телеметрия почти не влияет на линк. Донгл не обязателен.
- **ELRS 2.4 ГГц:** для телеметрии, тем более для дальней высокочастотной,
  **лучше ESP-NOW + USB-донгл**. WiFi-бэкпак делит 2.4 ГГц с линком, добавляет
  beacons/management/трафик телефона и в WiFi-режиме всё равно может слать ESP-NOW-кадры.
- **ELRS 2.4 ГГц, близко и низкая телеметрия:** WiFi может быть достаточным, если антенны разнесены и LQ не проседает. Но это компромисс, а не рекомендуемый основной путь.
- **Нужен нативный MAVLink/QGC:** это отдельный сценарий — WiFi-бэкпак в `Link Mode = MAVLink`. USB-донгл v1 отдаёт CRSF и для нативного MAVLink не подходит.
- **Нет OTG/USB host на телефоне:** USB-донгл невозможен, остаётся WiFi.

## 1. Диапазоны: кто с кем делит эфир

| Линк дрон↔аппаратура | Радио бэкпака | Пересечение | Что это значит |
|---|---|---|---|
| 900 МГц | 2.4 ГГц WiFi/ESP-NOW | Нет общего диапазона | WiFi/ESP-NOW почти не мешают линку; возможно только внеполосное блокирование при очень близких антеннах |
| 2.4 ГГц | 2.4 ГГц WiFi/ESP-NOW | Один диапазон | WiFi/ESP-NOW могут создавать коллизии и поднимать шум; влияние зависит от airtime, канала, антенн и трафика |

Практический вывод: **900 МГц — лучший выбор для дальних полётов с
WiFi-телеметрией; 2.4 ГГц — для близких полётов, а телеметрию лучше уводить
в ESP-NOW-донгл.**

## 2. WiFi-телеметрия бэкпака

Как работает:

- бэкпак поднимает WiFi AP или подключается к сети как STA;
- телефон/ПК подключается к AP или находится в той же сети;
- телеметрия идёт UDP-пакетами;
- в WiFi-режиме бэкпак также может продолжать отправлять ESP-NOW-телеметрию
  (для VRX-бэкпака/очков), то есть радио работает ещё активнее.

Плюсы:

- не нужен донгл, кабель и OTG;
- работает с существующим Android-приложением и `tlm_viewer.py`;
- удобно на стенде и для быстрой проверки;
- при 900 МГц-линке влияние на линк минимально.

Минусы:

- WiFi AP/STA добавляет beacons, management, DHCP/ARP;
- телефон рядом с аппаратурой тоже передаёт в 2.4 ГГц;
- при 2.4 ГГц-линке возможны коллизии с FHSS;
- при высокой телеметрии и/или загруженном эфире LQ может проседать;
- в поле надо поднимать AP/сеть, следить за каналом и клиентами.

## 3. ESP-NOW и USB-донгл

Как работает:

- бэкпак переводится в `Telemetry → ESP-NOW`;
- телеметрия идёт короткими ESP-NOW-кадрами на канале 1;
- USB-донгл ESP32-C3 принимает ESP-NOW и отдаёт CRSF в телефон по USB UART;
- телефон может оставаться без WiFi, интернет для карты — через мобильные данные.

Плюсы:

- нет WiFi AP/beacons/DHCP и трафика телефона в 2.4 ГГц;
- меньше средний airtime у бэкпака;
- телефон может быть без WiFi;
- предсказуемый USB serial, без настроек сети;
- лучше подходит для 2.4 ГГц-линка, высокой телеметрии и дальних полётов
  в пределах 2.4 ГГц.

Минусы:

- нужен донгл, OTG и кабель;
- телефон не заряжается одновременно без хаба;
- донгл сам является ещё одним 2.4 ГГц-радио (хотя с низким duty cycle);
- нужна отдельная тестовая Android-заглушка или поддержка в приложении;
- нативный MAVLink так не получить: по ESP-NOW идёт CRSF.

## 4. Что именно страдает в линке

- **Основная жертва — приёмник TX-модуля** (downlink/телеметрия), потому что
  радио бэкпака физически рядом.
- **Uplink управления** страдает меньше: его передаёт TX-модуль, а бэкпак —
  отдельное радио.
- **RX дрона** может слышать бэкпак только вблизи: стенд, взлёт/посадка.
- **Чем больше телеметрии**, тем больше airtime: 10 GPS/с, высокий TLM ratio,
  MAVLink-поток — всё это увеличивает нагрузку на 2.4 ГГц в обоих режимах.
- **WiFi-режим** добавляет фиксированную нагрузку (beacons/management) даже без
  активного трафика; **ESP-NOW** — только короткие кадры телеметрии и ACK.

## 5. Таблица сценариев

| Задача | Линк | Рекомендуемый путь | Почему |
|---|---|---|---|
| Дальний полёт | 900 МГц | WiFi-бэкпак | Разные диапазоны; донгл не нужен |
| Дальний полёт | 2.4 ГГц | ESP-NOW + USB-донгл | Меньше same-band airtime, телефон без WiFi |
| Фристайл близко | 2.4 ГГц | WiFi допустим при низкой телеметрии | Близко и мало кадров; следить за LQ |
| Фристайл + 10 GPS/с | 2.4 ГГц | ESP-NOW + USB-донгл | Высокая телеметрия; WiFi добавляет лишний airtime |
| QGC / нативный MAVLink | 900 МГц | WiFi + `Link Mode = MAVLink` | MAVLink идёт только по WiFi; 900 МГц не пересекается с 2.4 |
| QGC / нативный MAVLink | 2.4 ГГц | WiFi + MAVLink как компромисс; лучше 900 МГц | Same-band нагрузка; донгл v1 — CRSF |
| Очки/VRX-бэкпак | 2.4 ГГц | ESP-NOW | WiFi добавляет лишний airtime |
| Поле без WiFi | любой | USB-донгл | Не нужна сеть/AP |
| Телефон без OTG | любой | WiFi | USB-донгл физически невозможен |

## 6. Когда WiFi достаточно

- ELRS-линк **900 МГц**, особенно дальние полёты.
- ELRS 2.4 ГГц, но полёты **близко**, телеметрия низкочастотная, антенны
  разнесены, эфир не забит.
- Нужен **нативный MAVLink** от FC/QGC: бэкпак в `Link Mode = MAVLink` и
  `Telemetry = WiFi`.
- Не хочется покупать донгл, возиться с OTG и отдельным приложением.
- Нужно быстро посмотреть телеметрию на стенде или в поле с ноутбуком.

## 7. Когда покупать и прошивать USB-донгл

Явная рекомендация: **для ELRS 2.4 ГГц и любой серьёзной телеметрии — донгл.**
Конкретно:

- 2.4 ГГц-линк и нужна телеметрия на дальности или с высокой частотой;
- 10 GPS/с, высокий TLM ratio, частые кадры attitude/battery;
- хочется **выключить WiFi телефона** и убрать AP/beacons из эфира;
- нужен предсказуемый USB serial без сети и DHCP;
- бэкпак должен оставаться в ESP-NOW (например, для VRX/очков);
- поле без WiFi-инфраструктуры.

Когда донгл **не нужен**:

- 900 МГц + WiFi уже решает задачу;
- нужен именно нативный MAVLink, а не CRSF-путь;
- нет OTG/USB host на телефоне;
- не готовы к кабелю, OTG и отдельному приложению;
- телеметрия низкочастотная, полёты близкие.

## 8. OTG и ESP32-C3: что именно нужно

Ключевое: **ESP32-C3 не работает USB-хостом.** В схеме «донгл в телефоне»
хостом выступает телефон, а C3 — USB-устройство. Поэтому OTG нужен **телефону**,
а не C3.

| Сценарий | Нужен OTG? | Кто хост | Что видит телефон | Комментарий |
|---|---|---|---|---|
| Телефон + C3 DevKitM-1 (CP2102N) | Да | Телефон | USB-UART CP210x | Текущая прошивка проекта; нужен OTG-адаптер и data-кабель |
| Телефон + C3 с native USB CDC | Да | Телефон | CDC-ACM | CP2102N не нужен, но прошивку надо перевести с `Serial0` на USB CDC |
| Телефон + C3 + внешний USB-UART | Да | Телефон | CP210x/CH340 | То же, что DevKitM-1, но мост отдельный |
| ПК/ноутбук + C3 DevKitM-1 | Нет | ПК | USB-UART CP210x | OTG не нужен; удобно для прошивки и стенда |
| Телефон без USB host/OTG | — | — | — | USB-донгл невозможен; только WiFi |
| Телефон + OTG + powered hub | Да | Телефон/хаб | USB-UART | Позволяет заряжать телефон; нужен качественный хаб |

Что это значит для покупки:

- **C3 DevKitM-1 (CP2102N)** — самый простой путь: соответствует текущей
  прошивке, телефон видит USB-UART, нужен OTG-адаптер.
- **C3 SuperMini/native USB** — тоже возможен, но прошивку придётся переделать
  на вывод в USB CDC; OTG телефону всё равно нужен.
- **OTG-адаптер** обязателен для любого USB-донгла: USB-C→USB-A female +
  USB-A→micro-USB data, либо готовый USB-C→micro-USB OTG data-кабель.
- **Charge-only кабели не подходят** — нужен data-кабель.
- **Одновременная зарядка** — только через powered USB-C hub; не все телефоны
  и хабы это умеют.

## 9. Список покупок для USB-донгла

| Что | Зачем | Примечание |
|---|---|---|
| ESP32-C3-DevKitM-1 | Донгл | CP2102N, micro-USB; соответствует текущей прошивке |
| USB-C→USB-A female OTG-адаптер | Телефон как хост | Проверить поддержку USB host |
| USB-A→micro-USB data-кабель | Подключение донгла | Не charge-only |
| Или USB-C→micro-USB OTG data-кабель | Альтернатива адаптеру+кабелю | Должен быть с data-линиями |
| Micro-USB data-кабель для ПК | Прошивка/стенд | Не charge-only |
| Android-телефон с OTG, Android 7+ | Приёмник | Нужен USB host |
| Powered USB-C hub (опционально) | Зарядка + донгл | Не все телефоны/хабы поддерживают |
| Корпус/крепление (опционально) | Эксплуатация | Держать антенну донгла подальше от антенны TX |

Для прошивки нужен ПК с PlatformIO или готовый `firmware.bin`; APK заглушки
собирается из `android-stub/`.

## 10. MAVLink / QGC

- **Нативный MAVLink** с бэкпака возможен только по WiFi:
  `Link Mode = MAVLink` + `Backpack → Telemetry → WiFi`. FC должен отдавать
  MAVLink (Betaflight 2025.12.2, ArduPilot/PX4).
- На 900 МГц это хороший вариант: MAVLink идёт по 2.4 ГГц WiFi, линк — на
  900 МГц, диапазоны не пересекаются.
- На 2.4 ГГц это компромисс: WiFi-телеметрия делит диапазон с линком; для
  дальних полётов лучше 900 МГц + WiFi/MAVLink.
- **USB-донгл v1 отдаёт CRSF**, а не нативный MAVLink. Для QGC нужен либо
  WiFi-путь, либо отдельный MAVLink-мост/расширение прошивки.
- Для 10 GPS/с в MAVLink-WiFi: `mavlink_pos_rate = 10`; подробности — в
  `docs/ELRS-RATE-TELEMETRY-CHEATSHEET.md`.

## 11. Чеклист перед полётом

- Разнести антенны бэкпака/телефона/донгла и антенну TX-модуля.
- Для 2.4 ГГц-линка проверить LQ/RSSI/SNR на стенде в обоих режимах.
- В WiFi-режиме убрать лишний трафик телефона, не ставить телефон на TX.
- При 2.4 ГГц и высокой телеметрии предпочесть ESP-NOW-донгл.
- Для 900 МГц дальних полётов WiFi обычно безопасен.
- Проверить, что бэкпак действительно в нужном режиме:
  `Telemetry → WiFi` или `Telemetry → ESP-NOW`.
- Для донгла: `Link Mode = Normal`, `Telemetry → ESP-NOW`, binding phrase
  в `secrets.h`.
- Не летать с просевшим LQ; сначала стенд/близкая дистанция.

## 12. Ограничения

- Выводы без измерений: реальное влияние зависит от конкретного бэкпака,
  TX-модуля, антенн, корпуса, канала и загруженности 2.4 ГГц.
- WiFi-канал, мощность и поведение AP/STA зависят от прошивки бэкпака.
- Телефон, его WiFi и положение относительно аппаратуры — важный фактор.
- ELRS 2.4 ГГц использует FHSS; WiFi/ESP-NOW на фиксированном канале могут
  пересекаться с частью хопов.
- Нативный MAVLink и CRSF-путь — разные сценарии; не смешивать.
